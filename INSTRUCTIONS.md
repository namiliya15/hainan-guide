# Исправление — не сохранялись изменения в старых карточках мест

## Причина

В базе данных было правило безопасности: редактировать/удалять место можно только если `user_id`, записанный в этой конкретной строке, совпадает с ID твоей текущей учётной записи. Для мест, добавленных раньше (или там, где это поле не совпало по любой причине), обновление **молча не применялось** — Supabase не считает это ошибкой, просто "0 строк изменено", поэтому в интерфейсе не было видно вообще никакого сообщения о проблеме.

Важно: это должно было ломать не только добавление фото, но и **перетаскивание метки на карте** и **удаление** таких старых мест — под тем же самым правилом. Если что-то из этого тоже "не сохранялось" на старых карточках — это тот же самый баг, теперь всё должно чиниться разом.

## Исправление

Права на добавление/редактирование/удаление мест теперь привязаны к твоему **email**, а не к полю `user_id` в конкретной строке — так же, как уже было сделано для статей и предложений. Это надёжнее для сайта с одним администратором.

**Новый файл:** `supabase/migrations/008_fix_place_permissions.sql` — **обязательно выполнить** в SQL Editor, без этого старые карточки так и останутся нередактируемыми.

Заодно поправила мелкий сопутствующий баг рядом: при удалении последнего фото карточка сохраняла не пустое значение, а текст `"[]"`, что могло путать проверку "есть ли фото" в паре мест интерфейса.

**Изменённый файл:** `src/features/places/AddPlaceForm.jsx`.

**Важная оговорка:** это публичный тайловый эндпоинт Amap, который широко используется в открытых проектах, но он не является официально документированным API для внешних сайтов. ## 3. Расширенное описание места (Фаза 3)

У места теперь три отдельных поля вместо одного общего описания:
- **Время работы** (`working_hours`) — показывается иконкой 🕐 на карточке
- **Стоимость** (`price_info`)
- **Описание** (`description`) — как раньше
- **Дополнительно** (`extra_info`) — любые доп. детали (как добраться, лайфхаки)

Заполняются в форме добавления/редактирования (доступна только админу).

**⚠️ Важно — нужно применить SQL-миграцию.** При изучении схемы БД обнаружила несостыковку: в `supabase/schema.sql` поля `photo_url`, `lat`, `lng` были помечены `NOT NULL`, а код приложения (и старый, и новый) пишет в поле `photos` (которого не было в таблице) и допускает место без координат. Это могло вызывать ошибку при сохранении места без фото по URL/без координат.

**Как применить:** зайди в Supabase Dashboard → SQL Editor → открой файл `supabase/migrations/002_place_details_and_fixes.sql` из архива → вставь содержимое → Run. Это добавит новые поля и уберёт лишние NOT NULL. Безопасно запускать даже если что-то из этого уже было исправлено вручную раньше.
