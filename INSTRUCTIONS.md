## 2. Новая логика приложения

- Главная страница **публичная** — можно смотреть места, искать, пользоваться картой без входа.
- Вход нужен только для избранного (при попытке без входа — окно с просьбой войти) и админ-функций.
- Роутинг: `/` — главная, `/articles` — заглушка страницы статей.
- Дизайн из макета: hero, линия берега, плавающий поиск, горизонтальные категории, карточки одинаковой высоты с раскрытием текста, тёмная тема.
- Поиск ищет по всем местам сразу, независимо от категории.

## 3. Расширенное описание места (Фаза 3)

У места теперь три отдельных поля вместо одного общего описания:
- **Время работы** (`working_hours`) — показывается иконкой 🕐 на карточке
- **Стоимость** (`price_info`)
- **Описание** (`description`) — как раньше
- **Дополнительно** (`extra_info`) — любые доп. детали (как добраться, лайфхаки)

Заполняются в форме добавления/редактирования (доступна только админу).

**⚠️ Важно — нужно применить SQL-миграцию.** При изучении схемы БД обнаружила несостыковку: в `supabase/schema.sql` поля `photo_url`, `lat`, `lng` были помечены `NOT NULL`, а код приложения (и старый, и новый) пишет в поле `photos` (которого не было в таблице) и допускает место без координат. Это могло вызывать ошибку при сохранении места без фото по URL/без координат.

**Как применить:** зайди в Supabase Dashboard → SQL Editor → открой файл `supabase/migrations/002_place_details_and_fixes.sql` из архива → вставь содержимое → Run. Это добавит новые поля и уберёт лишние NOT NULL. Безопасно запускать даже если что-то из этого уже было исправлено вручную раньше.

## 4. Карта (Фаза 4)

- Одиночный тап по метке — всплывает название места (стандартный Leaflet Popup).
- Двойной тап — открывается карточка места (`PlaceModal`) поверх карты: тёмный фон, крестик в углу для закрытия, без скролла к карточке в списке.
- Кнопка "Моё местоположение" — по запросу (не автоматически) показывает на карте, где находится пользователь.
- Для админа сохранено прежнее поведение: клик по карте добавляет точку, маркеры перетаскиваются.

**Не включено:** замена карты на Amap/другой провайдер и построение маршрута — см. план, это отдельный пункт (можно сделать быстро через диплинки, но нужно отдельно проверить актуальную схему ссылок).

## 6. Как залить на GitHub (без терминала)

1. Открой репозиторий `hainan-guide` на GitHub.
2. Удали старую папку `src` целиком.
3. **Add file → Upload files** — перетащи папку `src` из архива (структура сохранится).
4. Так же замени: `package.json`, `tailwind.config.js`, `index.html`, `supabase/schema.sql`.
5. Добавь новый файл `supabase/migrations/002_place_details_and_fixes.sql` — и обязательно выполни его в Supabase SQL Editor (см. пункт 3 выше — это не применится само по себе просто от заливки на GitHub).
6. Остальное (`vite.config.js`, `postcss.config.js`, `.env.example`, `.gitignore`, `vercel.json`, `public/`, `DEPLOYMENT.md`) не менялось.
7. Commit changes — Vercel пересоберёт сайт сам.
